MÔ HÌNH USE CASE TRONG PTTKHTTT



1\. Use Case là gì?

Mô tả chức năng của hệ thống mà người dùng có thể thực hiện.



2\. Thành phần



* Actor: người/đối tượng tương tác với hệ thống.
* Use Case: chức năng hệ thống.
* System: phạm vi hệ thống.
* Relationship: mối quan hệ giữa Actor và Use Case.



3\. Các quan hệ chính



* Association: Actor tương tác với Use Case.
* Include: một Use Case luôn sử dụng Use Case khác.
* Extend: một Use Case có thể mở rộng Use Case khác.
* Generalization: kế thừa giữa Actor hoặc Use Case.



4\. Mục đích



* Xác định chức năng hệ thống.
* Xác định người sử dụng hệ thống.
* Làm cơ sở cho phân tích và thiết kế hệ thống.



5\. Cách xây dựng



* Xác định Actor
* → Xác định chức năng
* → Xác định quan hệ
* → Vẽ biểu đồ Use Case
* → Mô tả từng Use Case

CHƯƠNG 4: GIẢM CHIỀU DỮ LIỆU 



1\. Giảm chiều dữ liệu là gì?



Giảm số lượng features nhưng vẫn giữ thông tin quan trọng.



2\. Tại sao cần giảm chiều dữ liệu?



* Giảm thời gian huấn luyện.
* Giảm chi phí tính toán.
* Dễ trực quan hóa.
* Loại bỏ feature dư thừa.
* Giảm nguy cơ Overfitting.



2.1. Giảm thời gian huấn luyện



Nhiều feature → tính toán nhiều → huấn luyện lâu hơn.



2.2. Giảm chi phí tính toán



Ít feature → ít bộ nhớ và tài nguyên hơn.



2.3. Dễ trực quan hóa



Giảm dữ liệu xuống 2D hoặc 3D để dễ biểu diễn.



3\. Phương pháp giảm chiều



* Feature Selection: chọn feature quan trọng.
* PCA: tạo các thành phần chính mới.
* LDA: giảm chiều dựa trên khả năng phân biệt lớp.



4\. PCA

Phương pháp phổ biến, biến đổi dữ liệu nhiều chiều thành ít chiều hơn nhưng cố gắng giữ thông tin quan trọng.



5\. Ưu điểm



Nhanh hơn.

Ít tài nguyên hơn.

Dễ quan sát dữ liệu.



6\. Nhược điểm



Có thể mất thông tin.

Feature mới khó giải thích.
