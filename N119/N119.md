CƠ SỞ DỮ LIỆU CASSANDRA – NoSQL

1\. Cassandra là gì?



Cassandra là hệ quản trị CSDL NoSQL dạng Column-Family, được thiết kế để lưu trữ và xử lý khối lượng dữ liệu rất lớn trên nhiều máy chủ.



Cassandra phù hợp với các hệ thống cần:



* Tốc độ đọc/ghi cao.



* Dữ liệu lớn.



* Nhiều người dùng truy cập đồng thời.



* Khả năng hoạt động liên tục.



* Dễ mở rộng bằng cách thêm máy chủ.

2\. Đặc điểm của Cassandra



* Phân tán: dữ liệu được chia và lưu trên nhiều Node.



* Không có máy chủ trung tâm: các Node hoạt động ngang hàng.



* Mở rộng ngang: có thể thêm Node khi dữ liệu tăng.



* Chịu lỗi tốt: một Node gặp sự cố, hệ thống vẫn có thể hoạt động.



* Tốc độ cao: tối ưu cho các thao tác đọc/ghi lớn.



* Không sử dụng JOIN như SQL: dữ liệu thường được thiết kế theo cách phục vụ trực tiếp cho truy vấn.

Trong Cassandra, Primary Key rất quan trọng, vì nó quyết định dữ liệu được phân vùng và sắp xếp như thế nào.

Primary Key có thể gồm:

PRIMARY KEY (Partition Key)



hoặc:

PRIMARY KEY ((Partition Key), Clustering Key)



4\. Partition Key – Khóa phân vùng



* Partition Key là phần quan trọng nhất của Primary Key, dùng để xác định Partition chứa dữ liệu.



* Cassandra sử dụng Partition Key để quyết định dữ liệu sẽ được lưu trên Node nào trong cụm Cassandra.

Ví dụ:

CREATE TABLE SinhVien (

&#x20;   ma\_sv INT PRIMARY KEY,

&#x20;   ho\_ten TEXT,

&#x20;   lop TEXT

);



Ở đây:

ma\_sv → Partition Key



Mỗi ma\_sv sẽ tạo một Partition riêng.

Ví dụ:

ma\_sv = 1 → Partition 1

ma\_sv = 2 → Partition 2

ma\_sv = 3 → Partition 3



Partition Key dùng để làm gì?

Partition Key

&#x20;     ↓

Xác định Partition

&#x20;     ↓

Xác định nơi lưu dữ liệu

&#x20;     ↓

Tăng tốc truy vấn



Điểm cần nhớ: Cassandra rất phụ thuộc vào Partition Key. Nếu thiết kế Partition Key không tốt, dữ liệu có thể bị tập trung quá nhiều vào một Partition, gây mất cân bằng tải.

5\. Clustering Key – Khóa sắp xếp



Clustering Key dùng để sắp xếp các Row bên trong cùng một Partition.



Ví dụ:

CREATE TABLE DonHang (

&#x20;   ma\_khach\_hang INT,

&#x20;   ngay\_dat DATE,

&#x20;   ma\_don\_hang INT,

&#x20;   tong\_tien DECIMAL,

&#x20;   PRIMARY KEY ((ma\_khach\_hang), ngay\_dat)

);



Trong đó:

Partition Key:

ma\_khach\_hang



Clustering Key:

ngay\_dat



Ví dụ khách hàng 1 có nhiều đơn:

Partition khách hàng 1



ngay\_dat       ma\_don\_hang

2026-01-01     101

2026-01-05     102

2026-01-10     103

2026-02-01     104



Các đơn hàng có cùng ma\_khach\_hang nằm trong cùng Partition, sau đó Cassandra sắp xếp chúng theo ngay\_dat.
